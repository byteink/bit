# Expected pre-opt IR divergences between the Zig seed (`bit-seed`) and the
# self-hosted compiler (`bit`), consumed by scripts/selfhost-diffir.sh.
#
# This file is the gate, not a note. The script fails when a path ENTERS this
# set (a new regression) AND when one LEAVES it (a gap that closed and was not
# deleted here). Both directions matter: MISMATCH held at 4 across a 125-commit
# integration while only one file was ever named, so a known gap closing as a
# real regression opened would have read as "no change" (#1469).
#
# Format: one repo-relative path per line, `# reason` after it. Every entry
# needs a reason naming the underlying defect — an entry that only says "known"
# is an excuse, not a gap.
#
# Shrinking this list is the point. Delete an entry the moment its cause is
# fixed; the gate will tell you when that happens.

# --- FloatLit formatting parity (2 files) ---
# `bit`'s float-to-decimal printing truncates to ~30 significant digits, where
# the seed emits the full exact decimal expansion of the f64. Byte-exact parity
# needs a real `parseFloat`/shortest-representation primitive (std.fmt-grade):
# a naive converter drifts by 1 ULP, and 1 ULP flips the shortest digit string.
# Visible as `const_float f64 0.000...005` (seed) vs `0.000...000` (bit).
tests/cases/run_float_bitexact.bit   # float literal printed truncated, not exact-decimal
tests/cases/run_float_round.bit      # same FloatLit formatting gap, incl. 1e308 / denormals

# --- Generic type substitution in lowering: RETIRED (#1540) ---
# `run_generic_nested.bit` was here and is now closed. `lowerFieldAccess` took a
# field READ's result type straight off the declared field node with `noSubst()`,
# so `p.b` on a `Pair<i64>` emitted `field_get ... <T>`. `checkMember` already
# substitutes the receiver's type arguments, so lowering now prefers the
# checker's answer and keeps the declared type only when the parameter survives.
# The same pass substituted the composite-literal field hint (`items: []T` on a
# `Stack<i64>{...}` lowered its initializer under the bare `[]T`, minting the
# slice with is_ref SET — the GC walked plain integers as pointers).
#
# `run_generic_composite_result.bit` was retired earlier (#1485): its `[]<T>` /
# `fn(i64) <untyped>` leak had the same root cause as the four stubbed
# std/testing instances — `genericEnvOf` bound only the type-param id recorded
# during the collect pass, while the body had been checked against the last
# `T` registered in the module. Binding both ids substitutes it away.

# --- Methods on generic types: two different lowering models (1 file) ---
# #1325 landed generic-struct methods in both compilers, but they monomorphize
# differently, so the IR text cannot match until the models converge. The seed
# emits one body per receiver instantiation, named `<method>$t<typeid>`, with
# every type substituted. `bit` keeps a single body against the TEMPLATE and
# substitutes at the call site (the model its generic structs already use), so
# the IR still shows `[]<T>` and one shared instance. Both produce the same
# OBSERVABLE result — the `// run` case passes on both compilers, and
# scripts/selfhost-diffexamples.sh (the end-to-end guard) is clean.
#
# The remaining defect is narrower than it was, and now precisely located
# (#1540). Every `<T>` leak OUTSIDE a method body is gone; what is left is that
# `bit` has no NOMINAL type instantiation. check.bit resolves a `GenericInst`
# type node straight to its base named type (typeFromNodeIn, `Tag.GenericInst`
# -> `resolveNamed`), so `Stack<i64>` and `Stack<string>` share one TypeId and
# therefore one `$t<id>` mangled body. The seed mints a distinct nominal TypeId
# per instantiation (check.zig `instantiations` + `inst_by_result` +
# `instantiateRecursive`/`reinstantiate`), which is where its `$t34`/`$t37` come
# from. `bit` records generic FUNCTION instantiations (ctx.instantiations) but
# has no equivalent for structs/enums/interfaces.
#
# Closing it therefore needs BOTH: (a) per-instantiation nominal TypeIds in
# check.bit, and (b) interning them in the seed's lazy DFS first-touch order, or
# the numbers in `$t<id>` disagree even when the bodies do not — the type-id
# ordering divergence that already blocks the sha256 method mangling. (a) alone
# renumbers every type id in the corpus, so it must land with (b) or --dump-types
# parity goes red across the board.
tests/cases/run_generic_method.bit            # bit has no nominal type instantiation: Stack<i64>/Stack<string> share one TypeId
