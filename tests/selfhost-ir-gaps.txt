# Expected pre-opt IR divergences between the Zig seed (`bit-seed`) and the
# self-hosted compiler (`bit`), consumed by scripts/selfhost-diffir.sh.
#
# This file is the gate, not a note. The script fails when a path ENTERS this
# set (a new regression) AND when one LEAVES it (a gap that closed and was not
# deleted here). Both directions matter: MISMATCH held at 4 across a 125-commit
# integration while only one file was ever named, so a known gap closing as a
# real regression opened would have read as "no change" (#1469).
#
# Format: one repo-relative path per line, `# reason` after it. Every entry
# needs a reason naming the underlying defect — an entry that only says "known"
# is an excuse, not a gap.
#
# Shrinking this list is the point. Delete an entry the moment its cause is
# fixed; the gate will tell you when that happens.

# --- FloatLit formatting parity — CLOSED (#1539) ---
# `run_float_bitexact.bit` and `run_float_round.bit` were here. The cause was
# never the conversion ALGORITHM, which is why "needs a std.fmt-grade shortest
# -representation primitive" was the wrong diagnosis to inherit: both compilers
# already format through Zig's `{d}`. The seed calls it in-process; `bit` calls
# it through `bit_rt_string_from_float`, whose output buffer was 32 bytes.
#
# `{d}` on an f64 is POSITIONAL decimal always, never scientific, so DBL_MAX is
# 309 characters and the negative smallest subnormal is 327. `bufPrint` returned
# `NoSpaceLeft` correctly — but `libbitrt` is built ReleaseSmall, where the
# `catch unreachable` receiving it is undefined behaviour rather than a panic,
# and it degraded to handing back the unfilled 32-byte buffer. Both files
# diverged at exactly 32 characters, which is the tell.
#
# Sizing the buffer to the real bound and failing loudly instead of via
# `unreachable` closed both. The bug was never IR-specific: every Bit program
# printing a float wider than 32 characters was silently truncating it.

# --- Generic type substitution in lowering: RETIRED (#1540) ---
# `run_generic_nested.bit` was here and is now closed. `lowerFieldAccess` took a
# field READ's result type straight off the declared field node with `noSubst()`,
# so `p.b` on a `Pair<i64>` emitted `field_get ... <T>`. `checkMember` already
# substitutes the receiver's type arguments, so lowering now prefers the
# checker's answer and keeps the declared type only when the parameter survives.
# The same pass substituted the composite-literal field hint (`items: []T` on a
# `Stack<i64>{...}` lowered its initializer under the bare `[]T`, minting the
# slice with is_ref SET — the GC walked plain integers as pointers).
#
# `run_generic_composite_result.bit` was retired earlier (#1485): its `[]<T>` /
# `fn(i64) <untyped>` leak had the same root cause as the four stubbed
# std/testing instances — `genericEnvOf` bound only the type-param id recorded
# during the collect pass, while the body had been checked against the last
# `T` registered in the module. Binding both ids substitutes it away.

# --- Nominal instantiation: LANDED; interning-order tail remains (1 file) ---
# Per-instantiation nominal TypeIds are DONE (#1540). check.bit's `GenericInst`
# arm now mints a distinct nominal type per `(decl, args)` (selfhost/checkinst.bit
# `instantiateNamed`, the seed's `instantiateRecursive`/`reinstantiate`), lowering
# emits one substituted method body per receiver instantiation, and substitution
# re-instantiates nominal types so a method's `Stack<T>` result becomes
# `Stack<i64>`. `run_generic_arity_ok.bit` and `run_generic_nested.bit` are
# byte-identical as a result.
#
# CORRECTION to what this file used to claim: "(a) alone renumbers every type id
# in the corpus, so --dump-types goes red across the board" is FALSE, and cost
# this work an inflated estimate. `--dump-types` is name-keyed — it contains zero
# numeric ids, and an instantiation carries its BASE name (`Stack`, not
# `Stack<i64>`), exactly as the seed's `setDisplayName` does. difftypes stayed at
# MISMATCH=0 across all 174 compared files through the entire change.
#
# What is left in this one file is ONLY the numeric value of two `$t<id>`s
# (Stack<string> and Pair<i64,string>): every emitted symbol, body, parameter and
# result type otherwise agrees, with no `<T>` leak and no dangling call. The seed
# interns MORE types than `bit` at the moment it instantiates: `instantiateRecursive`
# runs `substMethod` over the template's whole method bucket inline, interning
# each substituted param/result composite right there, whereas `bit` copies method
# signatures in a later pass (`copyMethodsToInsts`, after `buildSignatures`) so
# those composites intern past every instance id. Closing it means moving the
# method-signature substitution into the mint, which needs signatures available
# before the instantiation pre-pass runs — a reordering of `checkModule`'s collect
# phase, not new machinery.
tests/cases/run_generic_method.bit            # instantiation-time interning order: seed interns substituted method sigs inside the mint, bit after it, so two $t<id> numbers differ
