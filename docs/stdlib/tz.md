# std/tz

The IANA time zone database, checked in and generated by `tools/gentzdata`
from a host's `/usr/share/zoneinfo`. Exists to hand `std/time`'s `extend()`
a zone database on a host with no zoneinfo tree of its own - a container,
for instance.

`std/time` never imports this module, so a program that imports only
`std/time` never links `data` in. Only a program that also imports `std/tz`
pays for it.

```bit
import * as time from "std/time"
import * as tz from "std/tz"

fn installZones(): bool {
  return time.extend(tz.data)
}
```

Host zone files always win: `time.zone()` falls back to whatever `extend()`
published only once its own read against the host's zoneinfo tree has
already failed. This database never overrides a zone the host already has;
it exists for hosts that have none.

### `data: string`

The database itself, in the blob format `time.extend()` (`std/time`)
expects: one TZif image per zone, copied byte for byte from the source
`/usr/share/zoneinfo` tree, indexed by zone name.

### `release: string`

The IANA release id the checked-in `data` was generated from, exactly as
the source tree's own `+VERSION` file held it - `"2026c\n"`, for example.
Regenerating is one command:

    bit run tools/gentzdata -- [zoneinfo-dir] [out-file]

`zoneinfo-dir` defaults to `/usr/share/zoneinfo`, `out-file` to
`stdlib/tz/data.bit`. Do not hand-edit `data.bit`; regenerate it instead.
