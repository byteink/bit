# The S3 error codes the Smithy model does not model: one `<Code> <HTTP status>` per line, sorted
# by code in byte order. A status of 0 is the table's "N/A".
# Source: the included error tables of the S3 API reference page ErrorResponses.html. AWS
# withdrew that page from docs.aws.amazon.com in 2026-09, so the pin is the Internet Archive
# capture of 2026-05-25 13:38:52 UTC, retrieved 2026-10-04:
#   https://web.archive.org/web/20260525133852id_/https://docs.aws.amazon.com/AmazonS3/latest/API/ErrorResponses.html
# sha256 of the page, decompressed: 3728dba8a70a62b9a06263b072e7b95237a6ec29c363b09aac63166afb114977
# The table has 134 rows for 132 codes. Two rows add no code: EntityTooLarge's second row
# (status 405 for a download; its first row's status is kept) and a row whose code cell reads
# "503 SlowDown" (a typo for SlowDown, which has its own row). The model models 8 of the 132
# (AccessDenied, BucketAlreadyExists, BucketAlreadyOwnedByYou, InvalidObjectState, InvalidRequest, NoSuchBucket, NoSuchKey, NoSuchUpload), so the base table contributes 124 unmodeled codes.
# Rows are extracted from the pinned page, not typed. Re-pinning the page means re-extracting all of them.
# #6823 includes these additional tables from the SAME decompressed-page pin:
# List of SELECT Object Content Error Codes: 111 rows, 108 new codes.
# List of Replication-related error codes: 3 rows, 1 new code.
# List of Amazon S3 Object Lambda error codes: 9 rows, 8 new codes.
# List of Amazon FSx-related error codes: 4 rows, 2 new codes.
# Plus 3 Outposts rows below: 130 additional rows, 121 new codes; 253 reference codes, 245 unmodeled.
# Repeated codes keep the same status: InternalError, MalformedXML, MethodNotAllowed,
# InvalidArgument, InvalidRequest, AccessDenied, SlowDown. No new status conflict.
# Retry classes follow the pinned Smithy classifier in emiterrors.bit, not SOAP fault prefixes.
# Excluded List of Tagging-related error codes (5 rows): the page identifies
# TagResource, UntagResource and ListTagsForResource for Storage Lens groups (s3control).
# Excluded List of Amazon S3 Storage Lens error codes (38 rows): dashboard configuration
# operations use s3control. Its second table, Storage Lens groups (20 rows), also uses s3control.
# Excluded List of Amazon S3 asynchronous error codes (10 rows): the page identifies
# DescribeMultiRegionAccessPointOperation (s3control); 200 is its operation-query status.
# Excluded List of Amazon S3 Access Grants error codes (25 rows): Access Grants and
# GetDataAccess operations use s3control; the returned credentials then call S3 separately.
# Excluded List of Amazon S3 Tables error codes (7 rows): table-management operations
# use the separate s3tables service, not the S3 object API.
# List of Amazon S3 on Outposts error codes (7 rows): exclude BadRequest (bucket
# deletion state), NoSuchOutpost (an Outpost control resource), and both InvalidRequest
# rows (access-point configuration/deletion),
# whose descriptions concern s3control. Include the remaining 3 documented rows:
# InvalidOutpostState 409, UnsupportedOperation 404, InsufficientCapacity 507.
# The first two codes' endpoint eligibility is unresolved: #6823 includes them
# conservatively because no evidence establishes s3control-only scope. Their documented
# statuses are unchanged; no data-endpoint response was observed. InsufficientCapacity
# duplicates the independently included FSx row with the same status (507).
